SQL

リレーショナル型 (RDB)

一言でいうと：
「超厳格なエクセルの表」
  • ルール（スキーマ）が絶対！ 「名前」「年齢」という列（カラム）を作ったら、それ以外の情報（趣味など）は絶対に書き込めません。
  • 整理整頓のプロ データが綺麗に並んでいるので、「年齢が15歳以上で、東京に住んでいる人」などの複雑な検索が超得意です。
  • 変更には弱い 後から「やっぱり趣味の列も追加しよう！」となると、何億件もある表全体を作り直す大工事（マイグレーション）が必要になります。
{/* NoSQL (Non-Relational) */}

NoSQL

非リレーショナル型

一言でいうと：
「なんでも入る魔法の自由帳」
  • 形はバラバラでOK！ A君は「名前と年齢」、B君は「名前と好きなゲーム」など、人によって持っているデータが違ってもポンポン保存できます。
  • 後からの変更に超強い 新しい機能ができて保存する項目が増えても、大工事は不要。そのまま新しい形のデータを放り込むだけです。
  • 複雑な検索は少し苦手 自由帳のように色んな情報が混ざっているので、「全員の年齢の平均を出す」のような表計算的な作業は苦手です。

絶対に間違えられない時

は SQL を使う！

🏦 銀行のシステム（お金の送金）

「残高」や「口座番号」というルールが途中で変わったら大事件です。1円のズレも許されない厳密な管理には、ルールの厳しいSQLが絶対です。

🏫 学校の成績・名簿管理

「全員の数学の平均点を出したい」など、表全体を使った複雑な計算を瞬時に行うのはSQLの得意技です。

{/* NoSQLのユースケース */}

柔軟にどんどん進化させたい時

は NoSQL を使う！

💬 LINEやSNSのメッセージ

文字だけの人、スタンプを送る人、写真を10枚送る人。形がバラバラなデータを、1秒間に何万件も保存するスピード勝負にはNoSQLが最適です。

🎮 ゲームのセーブデータ

アップデートで「新しい魔法」や「ペット機能」が追加されても、ルールが自由なNoSQLなら、古いデータにエラーを起こさず新しい項目を増やせます。

💡 現代の大きなアプリ（NetflixやAmazonなど）は、
「お金の管理はSQL」、「おすすめ映画の履歴はNoSQL」のように、
